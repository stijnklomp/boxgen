# AGENTS.md

`boxgen` is the **SYS-1.0 spec compiler**: YAML box spec → FreeCAD Python master → STEP/STL. It is a local CLI, not a service. Vocabulary: `GLOSSARY.md`. Decisions: `docs/adr/`. The authoritative generator contract is `docs/spec/docs/generator.md` (the SYS-1.0 spec is vendored at `docs/spec/`); the design standard there wins if they disagree.

## Commands

The host has no Rust toolchain by design. Two gates:

- `just check-docker` — authoritative; needs only Docker. Builds
  `boxgen/freecad:1.0.0` from `docker/freecad.Dockerfile` and runs the full gate
  inside it, including the FreeCAD toolchain assertion.
- `just check` — fast native gate for hosts that already have Rust 1.99.1 and
  `just`. Runs the Rust suite only; the FreeCAD test skips.

```bash
just check-docker
```

Without `just` on the host, the underlying commands are:

```bash
docker build --build-arg FREECAD_VERSION=1.0.0 \
  -f docker/freecad.Dockerfile -t boxgen/freecad:1.0.0 .

# The gate: fmt-check + lint (clippy -D warnings) + tests, with FreeCAD required.
docker run --rm -u "$(id -u):$(id -g)" \
  -e HOME=/tmp/boxgen-home \
  -e FREECAD_USER_HOME=/tmp/boxgen-freecad \
  -e CARGO_HOME=/tmp/boxgen-cargo \
  -e CARGO_TARGET_DIR=/tmp/boxgen-target \
  -e BOXGEN_REQUIRE_FREECAD=1 \
  -v "$PWD":/app -w /app boxgen/freecad:1.0.0 just check
```

`boxgen validate <spec>` is pure Rust and needs no FreeCAD; run it through the image like any other command. It prints a report to stdout and exits 0 for a valid spec (warnings included), or exits 2 with schema-path diagnostics on stderr.

`boxgen divide <spec> --path <p> --axis <x|y> --at <mm>` edits one division-tree node in place and re-validates before writing. `--path` is `root` (the default) followed by `.near` / `.far` steps, for example `root.far.near`. On a split, the given `--axis` and/or `--at` update that field and the omitted one is kept; on a leaf, both are required and the leaf becomes a split whose near child keeps the original compartment name. The edit uses the lossless `yaml-edit` crate, so only the target node changes and surrounding comments/formatting survive.

`boxgen build <spec> [--out DIR] [--publish]` is the build path: validate, copy the repository's `cad/` into `<out>/cad/` (default `build/<id>`), render `box.py`, verify `BOXGEN_FREECADCMD --version` reports `BOXGEN_EXPECT_FREECAD_VERSION`, run `freecadcmd`, then require `report.json`, `box.step`, `body.stl`, `box.FCStd`, and `lid.stl` (only when `lid: true`) to be non-empty before printing the measured summary. The division tree is compiled into the body (`cad/dividers.py`; ticket #8): every split is a 2.0 mm divider fused into the shell with 2.0 mm junction coves and a 0.4 mm top chamfer, and `report.json` carries the resolved `dividers` plan; validation warnings (a leaf below 15 mm) are merged into `report.json` without failing the build. The body must be one valid closed solid with positive volume and a watertight STL, and `report.json` must carry `body.floor_fillet_mm` as 2.0 or the 1.0 fallback (ticket #7); a reduced fillet also appears as a warning. A lid spec also requires one valid closed lid solid, a watertight `lid.stl`, and a `lid` report section whose `ribs` flag equals `lid_ribs`; the lid uses `cad/lid.py`'s standard dimensions (ticket #9). With `--publish` (#11), the spec's parent directory must be named after the spec `id` (`boxes/<id>/spec.yaml`); after a successful build, publish verifies `box.step`, `body.stl`, `notes.md`, and `lid.stl` (only when `lid: true`) non-empty, generates `notes.md` from the spec when the build has none, and copies them into the box folder — never `box.FCStd`, `report.json`, `box.py`, or `cad/`, never overwriting an existing `notes.md`, never rewriting `spec.yaml`. `tests/fixtures/minimal-build.yaml` is the 1x1x6U body fixture, `tests/fixtures/2x4-6u-lid.yaml` / `2x4-6u-lid-ribs.yaml` are the lid fixtures, and `tests/fixtures/4x4-6u-tree.yaml` / `4x4-6u-corner.yaml` are the golden-tree and deepest-legal-nesting fixtures; `tests/golden/minimal.box.py` and `tests/golden/2x4-6u-lid.box.py` pin the generated scripts byte-for-byte.

`boxgen coupon [--out DIR]` (default `build/coupon`) builds the calibration coupon (ticket #10, `docs/spec/docs/calibration.md` §2) through the same pipeline as `build`: the internal spec `coupon-1x1-6U-v1` (1 × 1, 6U, ribbed lid, single leaf, internal `coupon: true` flag) is constructed in Rust — the closed user schema still rejects `coupon` as an unknown field (exit 2) — rendered as the same `box.py`, run under `freecadcmd`, verified like any build (plus the `coupon` report section), and the summary is followed by the calibration reminder (print two coupons and one lid; run the nine tests in `docs/spec/docs/calibration.md`; record the result). The master adds the T-divider with `cad/dividers.py::build_coupon_divider` and records it in `report.json`'s `coupon` section (`wall`, `length_mm`, `thickness_mm`, `height_above_floor_mm`, `top_mm`, `top_chamfer_mm`), which `src/build.rs` requires for the coupon spec so the master cannot silently skip it. `tests/golden/coupon.box.py` pins the generated coupon script byte-for-byte.

`boxgen index [--boxes DIR]` (default `boxes`) scans `<DIR>/*/spec.yaml`, validates every spec with the `spec` module (invalid or malformed is exit 2, naming file and rule), and regenerates `<DIR>/INDEX.md` deterministically: one row per box sorted by box ID, columns box ID, `N × M` footprint, `U` height, contents (`contents.description`, else `notes`, else `—`, pipes escaped and newlines collapsed), catalogue stack group (orientation-independent: 4×4 A, 3×4 B, 2×4 C, 2×3 D, 1×4 E, other F), and the print date from `notes.md` (`Printed:`, `Print date:`, or `Printed on:`). The write goes through `INDEX.md.tmp` and an atomic rename. It needs no FreeCAD and matches the committed spec-repository format byte for byte.

`just` alone lists the recipes. Inside the image:

| Recipe | Purpose |
| --- | --- |
| `just check` | Native gate: `fmt-check`, `lint`, `test`; no FreeCAD needed. |
| `just check-docker` | Build the pinned image and run the full gate in it; CI runs this. |
| `just docker-build` | Build `boxgen/freecad:<freecad_version>`. |
| `just freecad-smoke` | Check `freecadcmd --version` and a trivial Part solid in the image. |
| `just fmt` / `just fmt-check` | Format / check formatting. |
| `just lint` | Clippy over all targets with warnings denied. |
| `just test` | Unit, integration, and doctests. |
| `just build` | Build the `boxgen` binary. |
| `just run -- --help` | Run the CLI. |

## Rules

- **FreeCAD is the only geometry engine.** Rust validates, renders the Python build script, invokes `freecadcmd`, and records results. Never implement mesh or CSG geometry in Rust.
- **Never trust `freecadcmd`'s exit status.** It exits 0 on unhandled Python exceptions, syntax errors, and missing scripts. A successful build requires the expected artifacts to exist non-empty, `report.json` to parse, and the body/STL invariants to hold; anything else is exit 3.
- **The build output is generated, never hand-edited.** `build/<id>/box.py` is rendered from the spec and pinned by a golden snapshot; `cad/` is copied in. The coupon is the same generated pipeline with the one internal spec (`coupon: true`); never approximate it from a user spec, and never hand-edit its geometry.
- **The spec is the source of truth.** `spec.yaml` defines one box; `build/<id>/` is generated and never hand-edited; `boxes/<id>/` changes only through a successful `--publish`, which never rewrites `spec.yaml` and never overwrites the human `notes.md`.
- **Publish verifies before it copies.** All required artifacts (`box.step`, `body.stl`, `notes.md`, and `lid.stl` for a lid spec) must exist and be non-empty before the first copy, so a failed publish leaves the box folder untouched. The publish target is the spec's own parent directory, which must be named after the spec `id`; there is no second location.
- **`boxes/INDEX.md` is generated.** `boxgen index` reads `<boxes>/*/spec.yaml` and writes the sorted table through `INDEX.md.tmp` and an atomic rename; never edit it by hand and never make a failed index truncate it.
- **One error contract.** Return `BoxgenError` from commands; map it to a process code only in `src/error.rs`. Exit codes are fixed: 0 success, 2 invalid spec, 3 geometry/build failure, 4 environment. Code 1 covers usage errors and commands that are not implemented during the bootstrap; it is never a contract failure code.
- **No server infrastructure.** Do not add axum, a tokio server, sqlx, Postgres, Valkey/Redis, RabbitMQ/lapin, pact, utoipa/OpenAPI, migrations, k8s, or compose services. v1 is a local CLI; a web UI is explicitly a v2 non-goal.
- **Config lives in `src/config.rs`.** Add a typed setting there (`BOXGEN_*`), never an ad-hoc `env::var` in command code.
- **stdout is for reports, stderr is for logs.** Keep it that way so `validate` and `index` output can be piped.
- **Do not remove the contract commands from `--help`.** Their argument shapes are the public interface even while they are stubs. Implement them in their ticket; keep `src/cli.rs` a parser and dispatcher.
- **Keep the spec schema closed.** Wall thickness, radii, lip dimensions, and print settings must never become spec fields. `parse` uses `deny_unknown_fields` at the root, in every division node, and in `contents`.
- **Validation is pure Rust.** `validate` enforces contract §3, §4 and §7 without FreeCAD. Warnings go to stdout and never fail the run; rule violations are `BoxgenError::InvalidSpec` and exit 2. The optional `contents` fit check follows standard §8: 2 mm per side and 5 mm above for rigid items, 5 mm per side and 10 mm above with `contents.soft: true` (soft items and cables); the 10 mm "where fingers must reach" rule stays a human sizing rule and has no schema field.
- **Run `just check-docker` before declaring work done.** It is the same gate CI runs (`.github/workflows/ci.yml`). Native `just check` is fine for quick Rust-only iteration, but any geometry claim needs the image.
- **FreeCAD has one canonical pin.** `freecad_version` in `justfile` drives the Docker build arg, the image tag, the version the test expects, and the CI workflow (which reads it from the justfile). Bump that one line. Never use `latest`.
- **The SYS-1.0 standard lives at `docs/spec/`.** It is authoritative for the generator: read the contract and standard there before touching validation or geometry, keep this crate's docs about the generator, and change the standard only as a deliberate spec change (system version bump + ADR under `docs/spec/docs/adr/`), never from a generator ticket.
- **The Gridfinity profiles never drift.** `cad/gridfinity.py` adapts the Gridfinity Workbench functions (LGPL-2.1; keep the attribution and `cad/LICENSE-LGPL-2.1`) instead of calling an installed workbench or redrawing the profile. `tests/gridfinity_interface.rs` measures the base and lip under the pinned FreeCAD; changing a profile means bumping SYS-1.0 and recording an ADR, never silently editing a number.
- **Internal fillets go through `cad/fillets.py`.** `fillet_with_fallback` owns the standard's 2.0 mm → 1.0 mm reduce-then-fail rule and the acceptance checks (`isValid()`, one solid, positive volume — `makeFillet` can return an invalid shape without raising). Never call `makeFillet` on a fused shell for an internal junction (OCC fails; pre-fillet the cutter or fuse cove rails instead), and never keep a sharp internal corner above the base: both radii failing is a `GeometryError` → exit 3. `build_body` reports the radius actually applied so `report.json` can record it and warn on the fallback.
- **Dividers are cove rails, not fillets.** `cad/dividers.py` fuses each split's 2.0 mm plate (0.4 mm top-edge chamfer) plus one horizontal 2.0 mm cove rail per face and one vertical cove column per span end, built as box minus quarter cylinder — the verified recipe, because OCC cannot fillet the fused shell. Every fuse is checked for one positive solid and the finished body for one closed shell. A junction that lands on the 1.75 mm inner corner arc is handled by placing the same 2.0 mm column on the *projected* wall face: the cove is larger than the corner radius and buries the acute notch with no sharp corner and no reduced radius. Contract validation makes that case unreachable (a split's far child is at least 12 mm deep, so no divider face or cross position can reach the 1.75 mm corner band); `cad/tests/dividers.py` forces it with synthetic trees anyway — keep the handling and the test.
- **The shell's cell webs tie interior feet to the body.** The interior cutter removes the body prism above the base zone except for the wall cove, so a foot that reaches no wall would hang on its 0.2 mm lift plate alone; `cad/shell.py` therefore fuses one web per internal 42 mm grid line, filling each 0.5 mm Gridfinity groove over the lift band. Without them a 4 × 4 body is five solids (`body interior with cell webs`). The web sits above the base zone, where a standard baseplate's rib has zero width, and its ends run 1.0 mm into the walls; do not move it down into the groove (it would break the baseplate fit) or widen it beyond the groove plus the 0.2 mm overlap.
- **The lid is a separate solid and stays out of the load path.** `cad/lid.py` builds it: 2.0 mm plate, 2.0 mm skirt, 0.30 mm per-side clearance to `lip_inner_offset + LID_CLEARANCE`, 1.40 mm corners, 0.6 mm bottom chamfer, 1.0 mm top roundover, 20 mm finger hole 14 mm from the +y edge. The plate top is `height_u * 7 - 1.0`, so the next body's base (`height_u * 7`) is 1.0 mm above it; never make the lid touch the body above or protrude beyond the footprint. Derive the clearance reference from `gridfinity` constants, not a re-typed 1.9. The 1.0 mm roundover on a 2.0 mm plate is at the geometric limit: its rejection is a recorded warning (`lid.roundover_mm: 0.0`), not a build failure. The ribs are a spec switch (`lid_ribs`), 0.15 mm interference, and require `lid: true`; keep them inside the plate footprint. Measured caveat for human checkpoint #14: a base seated in the lip's *contact* position (base bottom 0.35 mm below the lip bottom; `cad/tests/lid.py::_measure_stack`) overlaps the lid's plate edge and top face (`minimum_clearance_mm` about -1.15 mm), so a stacked body would rest on the lid, not the lip. The design pitch keeps the 1.0 mm gap; do not change the architecture without the checkpoint, and record any decision in an ADR.
- **The coupon is internal and fixed.** `boxgen coupon` constructs `coupon-1x1-6U-v1` in Rust (`src/build.rs::coupon_spec`) and runs it through the one `run_build` pipeline; the closed schema never accepts `coupon`, so no user spec can express it. `cad/dividers.py::build_coupon_divider` is the only coupon-specific geometry: a 2.0 mm T-divider centred on the interior's x = 0, 20.0 mm from the -y wall's inner face (the calibration's 20 mm weight foot rests on the top), top at `z_floor + divider_height(6) = 28.0`, 0.4 mm top chamfer, the same 2.0 mm floor rails and wall cove columns as a tree divider, no column at the free end, one closed solid. It accepts only 1 × 1 × 6U. `report.json`'s `coupon` section is required by `src/build.rs` for the coupon spec, so the master cannot silently skip the divider; keep `cad/tests/coupon.py`, `tests/coupon.rs`, and `tests/golden/coupon.box.py` in step with it. Do not change the coupon geometry without updating `docs/spec/docs/calibration.md`; the coupon is the calibration, not a convenience build.

## Crate map

- `src/main.rs` — thin entry: parse, load config, init logging, map `BoxgenError` to the exit code.
- `src/cli.rs` — clap definitions, help text, `AxisArg`, dispatch to the command modules.
- `src/spec.rs` — closed YAML schema, parsing, semantic validation, contents (rigid/soft fit) and estimate warnings, the validate report, the shared `invalid_spec` exit-code-2 mapping, and the id rule. `SYSTEM_VERSION` lives here.
- `src/tree.rs` — division tree, body geometry, leaf/divider validation, fixed-architecture constants, the documented mass/time estimate, and the in-place lossless `divide` helper.
- `src/build.rs` — `build`/`coupon` orchestration: the shared `run_build` renders `box.py`, copies `cad/` into the build directory, verifies the FreeCAD version, invokes `freecadcmd`, verifies artifacts and report invariants (including the coupon's T-divider section), merges validation warnings into `report.json`, and prints the summary; `build` adds publish into `boxes/<id>/` (`publish_target`, `publish_artifacts`, `render_notes`), and `coupon` builds the internal `coupon_spec()` into `build/coupon` and prints the calibration reminder (tickets #6-#11). The division tree is embedded in the generated script; Rust never compiles it.
- `src/index.rs` — deterministic `boxes/INDEX.md` generation and the `stack_group` catalogue mapping (ticket #11).
- `src/config.rs` — typed `BOXGEN_LOG`, `BOXGEN_FREECADCMD`, and `BOXGEN_EXPECT_FREECAD_VERSION`.
- `src/logging.rs` — stderr `tracing` subscriber; stdout stays clean.
- `src/error.rs` — `BoxgenError` and `ExitCode`, the single exit-code mapping.
- `cad/` — FreeCAD Python master, added from ticket #5 onwards. `cad/gridfinity.py` is the vendored, pinned Gridfinity base/lip profile module (LGPL-2.1-or-later, attribution in the header, text in `cad/LICENSE-LGPL-2.1`); it must import under `freecadcmd` with no workbench installed. `cad/geometry.py` owns `GeometryError` and the shared `require_one_solid(shape, what, *, closed=False)` guard every master module uses. `cad/shell.py` assembles the body shell (including the cell-boundary webs) and returns the `BodyResult` (shape plus the floor fillet radius applied) and measures the usable interior depth from the built body, `cad/dividers.py` compiles the division tree into `Divider` plates, coves, and chamfers fused into the shell (the axis-specific rails behind one `cove_rail` dispatcher) and owns `build_coupon_divider` (the calibration coupon's T-divider), `cad/lid.py` builds the inset friction lid (including the optional rib pair and the applied-roundover report), `cad/fillets.py` owns the 2.0 → 1.0 mm reduce-then-fail helper, `cad/build.py` exposes `build(spec, out_dir)` (handling the internal `coupon` flag) and exports STEP/FCStd/STL for the body and lid, and `cad/__init__.py` makes the package importable from the build directory. `cad/tests/interface.py`, `cad/tests/radii.py`, `cad/tests/dividers.py`, `cad/tests/lid.py`, `cad/tests/coupon.py`, and `cad/tests/step_slices.py` are the headless measurement scripts; `cad/tests/_harness.py` holds their shared scaffolding (the `BOXGEN_JSON:` marker, rounding, thin-slab section measurement, material probes, and the entry-point wrapper), and each script prints one marker line (`step_slices.py` slices an exported `box.step`, with wire boxes and enclosed areas, for the build and coupon tests).
- `docs/spec/` — the vendored SYS-1.0 spec: generator contract, design standard, workflow, calibration procedure, ADRs, box-spec template, empty registry. Authoritative for generator behaviour; change it only as a deliberate spec change (system version bump + ADR there), never from a generator ticket.
- `templates/box-spec.yaml` — copyable spec skeleton pinned by an end-to-end validate test; documents the optional `lid_ribs` switch.
- `tests/cli.rs` — process-level CLI contract tests.
- `tests/common/mod.rs` — the shared integration-test scaffolding: the `boxgen` command, fixture paths, the `BOXGEN_REQUIRE_FREECAD` gate, running `cad/tests/*.py` and parsing their marker, report readers (`value`/`number`/`flag`/`list_len`/`wire_box`), the millimetre assertions (`assert_close`/`assert_near`/`assert_close_list`), the fake launcher, and the STEP timestamp normaliser.
- `tests/validate.rs` — `validate` process tests: report, warnings, exit code 2.
- `tests/build.rs` — `build` process tests: golden scripts, end-to-end body, split-tree (golden fixtures, exported-STEP slices, warnings) and lid geometry, determinism, publish behaviour, and exit codes 1/2/3/4.
- `tests/index.rs` — `index` process tests: the committed format, the vendored spec-repository comparison (`docs/spec/`), and exit 2 for an invalid registry.
- `tests/fixtures/committed-INDEX.md` — copy of the spec's committed empty `boxes/INDEX.md`; the empty-index comparison that runs when `docs/spec/` is not checked out.
- `tests/golden/minimal.box.py` — byte-for-byte snapshot of the generated script for `tests/fixtures/minimal-build.yaml`.
- `tests/golden/2x4-6u-lid.box.py` — byte-for-byte snapshot of the generated script for the lid fixture.
- `tests/coupon.rs` — `coupon` process tests (ticket #10): the golden coupon script, the internal flag rejected in user specs, the default `build/coupon` with a fake launcher, the end-to-end coupon build (artifacts, report, reminder), the geometry via `cad/tests/coupon.py`, the exported-STEP slice areas at z = 20/29, determinism, exit codes, and the calibration-document feature table against the vendored `docs/spec/`; the geometry checks skip natively, mandatory with `BOXGEN_REQUIRE_FREECAD=1`.

- `tests/gridfinity_interface.rs` — pinned Gridfinity base/lip profile check: runs `cad/tests/interface.py` under `freecadcmd`, skips natively, mandatory with `BOXGEN_REQUIRE_FREECAD=1`.
- `tests/body_radii.rs` — body radii and internal-fillet check: runs `cad/tests/radii.py` under `freecadcmd` and pins the outer 3.75 / inner 1.75 / lip `OUTER_RADIUS - offset` / 2.0 floor cove radii, the 1.0 mm minimum above the base, the 0.4 mm base-cavity minimum, and the helper's reduce and failure paths; skips natively, mandatory with `BOXGEN_REQUIRE_FREECAD=1`.
- `tests/lid.rs` — lid geometry check: runs `cad/tests/lid.py` under `freecadcmd` and pins the plate/skirt thickness, 0.30 mm per-side clearance, 1.40 mm corners, 1.0 mm roundover, 0.6 mm chamfer, 20 mm finger hole at 14 mm, stack gap, 1x1 parity, and the optional 0.15 mm ribs; skips natively, mandatory with `BOXGEN_REQUIRE_FREECAD=1`.
- `tests/dividers.rs` — divider geometry check: runs `cad/tests/dividers.py` under `freecadcmd` and pins the 2.0 mm thickness, the golden tree's absolute near faces (x = -1.75, y = -31.75, x = 40.25) and full spans, top heights 15.0 / 28.0 / 49.0 / 70.0 mm, the 0.4 mm top chamfer, the 2.0 mm floor cove taper, T/wall junction probes, one split of a 4 × 4 body staying one solid (the shell's cell webs), and two synthetic corner-arc trees; skips natively, mandatory with `BOXGEN_REQUIRE_FREECAD=1`.
- `docker/freecad.Dockerfile` — Rust 1.99.1 + `just` + headless FreeCAD; the authoritative gate image. `freecad_version` in `justfile` is the pin.
- `scripts/calibration-wizard.sh` — the human #13 walkthrough: checks `build/coupon/`, steps through the Bambu Studio/X2D production recipe and the print, walks the nine `docs/spec/docs/calibration.md` tests stage by stage, resumes across the 1 h and 24 h load-test waits (state in `build/calibration/state.env`), and writes a dated record with the go/no-go, the calibration-record-table row, and a paste-ready issue comment. It never closes #13 or #14; it prints the `gh` commands for the human.

## Pitfalls

- The host has no cargo/rustc/just. If a command fails with "command not found", you forgot the container.
- `cargo fmt`, `clippy`, and `freecadcmd` come from `boxgen/freecad:1.0.0`. The plain `rust:1.99.1-slim-trixie` image has none of them, so use the pinned image for gates.
- Running the gate as a non-root UID needs `HOME`, `FREECAD_USER_HOME`, `CARGO_HOME`, and `CARGO_TARGET_DIR` under `/tmp`; the image pre-creates the documented paths world-writable. FreeCAD 1.0.0 segfaults if its user home is missing, so create a custom `FREECAD_USER_HOME` before using it.
- A non-root `bash -lc` login shell resets `PATH` and loses `/usr/local/cargo/bin`. Invoke commands directly or use `bash -c`.
- All five contract commands are implemented (the last stub, `coupon`, landed in #10) and must exit 0 or a contract code. `build` covers body-only, split-tree, and lid specs (tickets #6, #8, and #9) plus `--publish` (#11); `coupon` builds the internal calibration spec through the same pipeline. There is no stub left to keep failing; `--help` and the command surface stay stable.
- `divide` must never write on a failed edit. It resolves the path against the parsed tree, edits the YAML losslessly, re-parses and compares the whole spec, then runs the normal validator; any failure leaves the file byte-for-byte unchanged. Missing flags are usage errors (exit 1); unresolved paths and invalid results are invalid-spec errors (exit 2). A named leaf keeps its compartment on the near child; the far child is unnamed.
- `validate` accepts floating-point `contents` millimetre values but integer footprints, heights, and `at_mm`; negative or fractional `at_mm` is a parse error, while `at_mm < 12` is a semantic error.
- Box IDs accept both the generic lowercase kebab-case form and the standard `<N>x<M>-<height>U-<slug>-<rev>` form (`4x4-6U-example-v1`). The frozen standard wins over the generator contract's lowercase-only example. Arbitrary uppercase, empty segments, and path separators remain invalid; do not widen the validator beyond these two forms.
- `--publish` must never run before a successful build; do not populate `boxes/` from a failed run. It resolves the target first (the spec's parent must be named after the spec `id`), verifies all required artifacts before the first copy, generates `build/<id>/notes.md` only when absent, and never overwrites an existing `boxes/<id>/notes.md`.
- `index` writes `INDEX.md` through a fixed `INDEX.md.tmp` beside it and then renames; a failed write must leave an existing `INDEX.md` intact. An empty registry keeps the exact committed header with "No boxes recorded yet." and the em-dash row; a non-empty registry uses "Generated by `boxgen index`." and sorted rows. Pipe characters are escaped, newlines collapse to spaces, and the file ends with a newline after the last row.
- `index` sorts rows by box ID, not folder name. Folder names that do not match the spec `id` are allowed (only `--publish` enforces the `boxes/<id>/` layout), and directories without `spec.yaml` are skipped. The print date comes from `notes.md` lines starting `Printed:`, `Print date:`, or `Printed on:`; a placeholder with an empty value renders `—`.
- `freecadcmd` reports exit 0 when a script raises an unhandled exception, and re-runs the script. `cad/tests/interface.py` wraps its entry point and exits 1 on failure; keep that pattern in `cad/build.py` and verify artifacts, never just the exit code.
- FreeCAD resets `sys.dont_write_bytecode` to `False` at startup, so `PYTHONDONTWRITEBYTECODE=1` does not stop `__pycache__/`; `src/build.rs` removes the caches after the run and they are never artifacts.
- `tests/golden/minimal.box.py`, `tests/golden/2x4-6u-lid.box.py`, and `tests/golden/coupon.box.py` are compared byte-for-byte and `tests/build.rs`/`tests/coupon.rs` assert the files the build wrote. Change them only with an intentional generated-script change.
- The lip's inner profile is not monotonic under OCCT 7.8: a single multi-row loft through it self-intersects while `isValid()` still returns true and the volume goes negative. `cad/lid.py` therefore builds the skirt as stacked monotonic segments and every boolean is checked for one solid with positive volume; keep that recipe when touching the lid.
- The 1.0 mm lid roundover on the 2.0 mm plate is at the geometric limit. `makeFillet` may reject it; `build_lid` falls back to the sharp-but-valid plate and the report records `lid.roundover_mm: 0.0` with a warning. Do not turn that fallback into a build failure, and do not "fix" it by thinning the plate.
- `lid_ribs: true` with `lid: false` is an invalid spec (exit 2, naming both fields), not a silently ignored flag. The Python master repeats the check as a backstop.
- Do not rely on stdout for machine-readable FreeCAD output: the launcher prints banner and progress noise. `cad/tests/interface.py`, `cad/tests/radii.py`, `cad/tests/dividers.py`, `cad/tests/lid.py`, `cad/tests/coupon.py`, and `cad/tests/step_slices.py` emit a single `BOXGEN_JSON:` marker line that the Rust tests parse (through `cad/tests/_harness.py::emit`).
- `freecadcmd` discards Python stdout that was not flushed when the script returns; the headless measurement scripts must print their marker with `flush=True` (the shared `cad/tests/_harness.py` does) or the output silently disappears. The scripts import the master differently: `cad/tests/interface.py` adds `cad/` to `sys.path` and imports modules top-level, while `cad/tests/radii.py`, `cad/tests/dividers.py`, `cad/tests/lid.py`, and `cad/tests/coupon.py` add the repository root so they can import `cad.fillets` / `cad.dividers` / `cad.lid` as a package (and `cad.tests._harness` for the shared scaffolding).
- A multi-product STEP imports into a container `App::Part` with an origin (axes and planes), so `cad/tests/step_slices.py` filters candidates to `Part::Feature` objects with positive volume; the coupon STEP's `objects` are exactly `["Body", "Lid"]`. Slice wire areas come from `Part.Face(wire).Area` (the enclosed region, void side for an inner wire), which is how `tests/coupon.rs` proves the T-divider material in the exported artifact.
- `Shape.slice` section curves carry the kernel's section tolerance (measured about 0.0003 mm on the divider cove surfaces), so slice-derived checks use a 0.005 mm tolerance for coves while wall and divider face positions are exact; the divider tops are measured by bisection with a 0.01 mm probe against the plate centre. The 3U divider top (15.0 mm) sits inside the lip's neck transition (the interior cutter ends 2.3 mm below the lip bottom, at 14.7 mm), so a 3U divider's top 0.3 mm is inside the lip void: that is the standard's measured 3U geometry, not a bug.
- A junction that would land on the inner corner arc cannot occur in a valid spec: contract validation requires every split's far child to be at least 12 mm deep, which keeps every divider face and cross position at least 12 mm clear of the parent edge, while the 1.75 mm corner band starts only 1.75 mm from the wall. `tests/fixtures/invalid/corner-divider.yaml` pins that rejection; the master-level handling in `cad/dividers.py` and its synthetic-tree tests are defensive. Loosening a leaf minimum would make the case reachable, and the cove on the projected wall face already handles it (2.0 mm > 1.75 mm).
- The SYS-1.0 spec is vendored at `docs/spec/` (it was a separate local repository before 2026-10-18); `docs/spec/docs/generator.md` and `docs/spec/docs/standard.md` are authoritative. If it ever moves again, update the pointers in `README.md`, this file, and `docs/agents/domain.md`.
